# 通用性政策——本技能不得携带任何项目专属信息

> **级别：附录（维护者）** ｜ 什么时候读我：你要新增内容或对外发布 ｜ 不用读我：你只是使用者
> 入口与完整分级见 `INDEX.md`。

> 适用于 `fluctuation-analysis` 技能的全部内容：`SKILL.md`、`docs/`、`references/`、
> `windowcalc/`、`examples/`、`CHANGELOG.md`。
> **本文档是硬约束，不是建议**；`selftest.py` 有一项检查会扫描全文并直接判失败。

---

## 1. 两条硬规则

### 规则一：药物名 / 诱导剂名只允许来自**被引用的文献**

- 允许：文献里出现过、且**同段给出处**（DOI / 作者年）的药物名、诱导剂名、菌株名。
  例：`达托霉素/万古霉素（10.1128/aac.01414-25）`、`文献例 gkab583`。
- 允许：细菌遗传学的**标准选择标记**（链霉素 / 壮观霉素 / 利福平 / 夫西地酸 / 四环素 等）——
  它们是方法学词汇，不是某个课题的专有体系；但仍应在 `references/markers.md` 里说明其靶标与局限。
- **禁止**：本项目用的药物名、诱导剂名、靶点基因名、菌株代号。这些没有文献出处，
  写进通用技能＝把我们的实验当成通用知识。

### 规则二：默认值只允许来自**文献确证**的通用值

- 允许：文献报告的通用量级（并注明出处）、数学常数（`log₂`、`1.96`、rule of three 的 `3/n`）、
  以及标注 `[约定]` 的**操作上限**（如"单板 CFU ≤10⁷"），且必须写"按你的体系改"。
- **禁止**：由本地项目推导出来的任何数值——实测速率、泄漏比、诱导幅度、基因组大小、
  窗口代数、保护区大小、剂量、乘客数、F 值——无论它出现在
  代码默认值、示例数据、文档算例、"典型输出"，还是"经验值/推荐值"的口吻里。

---

## 2. 为什么这么严

技能是发给**别人**用的。我们自己的体系（菌株、药、诱导剂、实测 μ/M/F/G）一旦混进来，
读者会把它当成"通用推荐"——这是最隐蔽的错误来源：**数看着像建议，其实是别人的实验**。
更糟的是它不会报错：软件照跑，结论照出，只是默默地把我们的体系套到了别人的体系上。

## 3. 落地位置（三类载体，三种写法）

| 载体 | 怎么写 |
|---|---|
| **代码**（`windowcalc/`） | 缺参就拒绝并列清单，**不得回落到内置数**。2026-11-15 起 `--mu` / `--mu1` / `--nt-mean` / `--td` / `design-induction --nt` 均为必填 |
| **示例数据**（`examples/`） | 只允许两类：① **文献数据集**（Luria–Delbrück 1943、Demerec 1945、Rosche & Foster 2000 等，文件头注明出处）；② **明确标注的合成数据**（文件头写"合成，非实测、非默认"＋生成参数） |
| **文档**（`docs/`、`references/`、`SKILL.md`） | 教学算例一律用**符号**（`M_on` / `M_off` / `f` / `Nt` / `n_win`）；必须给数时，用文献数据集，或写"把你自己实测的 X 填进来" |

**一句话**：能用符号就用符号；必须给数就用文献的数；我们的数一律不出门。

### 新增文档的两条形式要求（2026-11-15）

1. **H1 下方必须有一行分级横幅**：`> **级别：必读/主路径/附录** ｜ 什么时候读我：… ｜ 不用读我：…`
   ——否则读者又多一个"不知道要不要点开"的入口
   （`selftest` 的「文档：分级横幅齐全」一项会检查）。
2. **能塞进已有文档的一节，就不新开一篇**。14 篇是上限（2026-11-15 由 19 篇合并而来），
   入口只有 `docs/INDEX.md`。**这一条现在由 selftest 现场数**（数 `docs/*.md`，超限直接红）——
   要加一篇得先合并掉一篇。

### 图也算"载体"

`selftest` 的守卫只能扫文本，扫不了像素——所以**图片必须靠人眼把关**，规则与文档相同：

- 技能里的图只画**结构**：相段、箭头、公式；纵轴写"示意，不标数值"，刻度用符号（`M_on` / `M_off` / `M_base`）。
- 不许把项目实测值画进图（哪怕加了"假设值"标注——假设值也是我们的实验，只是换了说法）。
- 每张图都配一个生成脚本（如 `docs/figures/make_cycle_schematic.py`），脚本入仓、可复现、可审。
- 项目自己的**数值版**图留在项目目录，不进技能。

## 4. 自动守卫

`selftest.py` 的「通用性」检查会扫描

```
SKILL.md  CHANGELOG.md  docs/*.md  references/*.md  windowcalc/*.py  examples/**
```

命中黑名单即失败，并打印 `文件:行:命中`。黑名单分两类（表在 `selftest.py` 的 `GENERIC_BANNED`）：

1. **名字**：本项目药物/诱导剂/靶点/菌株代号；
2. **数值指纹**：本项目实测或推导出来的特征数字（含"×倍"这类带单位的写法）。

**豁免**：`tests/`、`audit/`、`data/` 不在扫描范围（开发与历史记录，不进技能分发）。

> 守卫只挡"已知的泄漏"。新写的数字若不在表里，它不会报警——所以下面这张检查单仍然要做。

## 5. 新增内容前的五问

1. **这个名字来自哪篇文献？** 答不上来 → 删掉或改成通用描述。
2. **这个数字来自哪？** 文献（写出处）/ 你自己实测（→ 不许进技能）/ 纯算术（可以）。
3. **它是不是以"默认值 / 推荐值 / 典型值"的口吻出现？** 是 → 改写成"必须由你提供"。
4. **换一个完全不同的菌、完全不同的药，这段还成立吗？** 不成立 → 它就不是通用内容。
5. **跑过 `selftest.py` 的通用性检查了吗？**

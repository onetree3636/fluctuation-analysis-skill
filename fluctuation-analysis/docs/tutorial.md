# 10 分钟上手：从 40 管计数到突变率

> 假设你刚做完一次波动实验：30–40 管平行培养，涂了选择板，数了每管的抗性菌落数，
> 也测了终末细胞数（Nt）。目标：得到一个**突变率 μ** 和一个**置信区间**。

---

## 第 0 步：确认你有两样东西

1. **每管的抗性菌落数 r**（整数，0、1、2、…，偶尔有几百的 jackpot）；
2. **每管的终末细胞数 Nt**（单位 **CFU/管**，不是 CFU/mL）。

> ⚠️ 90% 的错误出在 Nt 单位。实验室常写"2×10⁸ CFU/mL"——如果一管是 2 mL，
> 那 **Nt = 4×10⁸ CFU/管**。两种输入方式工具都支持（见第 1 步）。

## 第 1 步：做成表格（Excel 直接给，也能用 CSV）

**最省事：Excel 文件直接给，不用另存为 CSV。** 第一列 r、第二列 Nt，表头可留可不留：

```
--input 我的计数.xlsx        ← .xlsx / .xlsm 都行，读第一个工作表
```

> 老格式 `.xls`（Excel 97-2003）读不了，会提示你另存为 `.xlsx` 或 `.csv`。

要 CSV 也可以（两种写法都行）：

**写法 A（Nt 已经是每管总数）**：
```csv
r,Nt
0,3.0e8
1,3.0e8
0,3.0e8
3,3.0e8
0,3.0e8
```

**写法 B（Nt 是 CFU/mL，加一列体积）**：
```csv
r,Nt,volume_mL
0,2.0e8,2
1,2.0e8,2
0,2.0e8,2
3,2.0e8,2
0,2.0e8,2
```
工具会自动算成 `Nt = 4×10⁸ CFU/管`。

> 用 Excel 时：**只保留两列（r 和 Nt）或加第三列体积**，**不要带"管号"列**。
> 列的顺序不能换——第 1 列必须是 r，第 2 列必须是 Nt。
> 存成 CSV 也行，中文 Windows 的 GBK 编码能读。

## 第 2 步：跑一条命令

```bash
windowcalc rate --input 我的数据.csv --label WT --field M_base
```

> `--field M_base` 的意思是"这段结果将来要填进菌株卡的 M_base 字段"——这样输出末尾的 YAML 片段
> 键名就是 `M_base`，可以整段粘过去。不加 `--field` 时键名会是 `WT`（人看的名字），粘进卡片会报缺 M_base。

如果你只有 Nt 的均值（CSV 里没有 Nt 列）：
```bash
windowcalc rate --input 我的数据.csv --nts 3e8                    # CFU/管
windowcalc rate --input 我的数据.csv --nts 2e8 --nt-unit per_mL --volume-mL 2   # CFU/mL × 2 mL
```

## 第 3 步：读输出（逐行）

```
输入：C=40 管｜r 合计=68（最大 9）｜Nt=3e+08 CFU/管
== WT ==
C=40  mean_r=1.70  median_r=1  p0=0.325
m (MSS-MLE)     = 1.4200   95%CI [0.9800, 2.0100]
m (p0 交叉核验) = 1.1200   有效区间内
μ = m/mean(Nt)  = 4.73e-09 per CFU per passage   95%CI [3.27e-09, 6.70e-09]
     （参照量级：野生型 E. coli ~1e-9；典型 mutator 1e-8–1e-6——若差几个数量级，先查 Nt 单位）
```

| 行 | 含义 | 怎么判断对不对 |
|---|---|---|
| `输入：C=… r 合计=…` | **先核对解析**：管数对不对、r 总和对不对 | 不对说明列读错了 |
| `m` | 每管突变事件数 | **≥0.3**（<0.3 要加管）；MSS-MLE 对 m **没有上界域**——「1.5–15」只是中位数法的域，别当成通用区间 |
| `95%CI` | 真值范围 | 越窄越好 |
| `p0 交叉核验` | 另一种算法 | 与 m 差 <2 倍算正常 |
| `μ` | **最终要报的数** | 与参照量级比：差 10 倍以上先查 Nt |

## 第 4 步：接下来做什么

| 你的下一步 | 命令 |
|---|---|
| 和另一组比（WT vs mutator） | `windowcalc compare --d1 WT.csv --d2 mutator.csv --labels WT,mutator` |
| 想知道要铺多少管 | `windowcalc power --mode precision --mu 2e-9 --nt-mean 3e8` |
| 想设计诱导剂浓度 | `windowcalc design-induction --n-doses 5` |
| 想算表达窗口 | `windowcalc optimize --strain 菌株卡.yaml --protocol 协议卡.yaml` |

> ⚠ **从 μ 到窗口有一个单位陷阱**：`rate` 给的是**单位点**速率（如 Rif/rpoB，~1e-9），
> 而菌株卡里的 `M_base/M_on/M_off` 要的是**全基因组每代**的乘客数（示例卡 0.004 = Drake 量级）。
> 两者差 10³–10⁶ 倍，**不能直接粘**。比值的活（M_off/M_base）可以照抄；
> 绝对负荷要另用 WGS 折算。详见 `docs/mutator-window.md` §4 的「M 的量纲」。
> 软件的兜底：`M_* < 1e-5` 时报告会亮红灯、`rate` 的输出片段也会写"不能直接粘"。

## 五个最常见的错误（工具会提示，但你要知道）

| 错误 | 现象 | 解决 |
|---|---|---|
| **Nt 用了 CFU/mL** | μ 偏大 2–10 倍（差一个培养体积） | 加 `volume_mL` 列或用 `--nt-unit per_mL` |
| **列顺序反了**（Nt,r） | 报错"第 1 列像 Nt" | 交换两列 |
| **带了管号列** | 报错"Nt=0 必须为正" | 删掉管号列，只留 r,Nt |
| **第二列是频率**（r/Nt） | 报错"第二列是 0/负数"或 μ 离谱 | 换成原始 Nt |
| **只涂了一部分没说** | μ 偏低（稀释抬高零管比例） | 加 `--fraction-plated 0.5` |

## 数字看着不对？按这个顺序查

1. **管数**：`输入：C=…` 和你实际管数一致吗？
2. **r 总和**：数一下原始表，一致吗？
3. **Nt 单位**：CFU/管 还是 CFU/mL？
4. **m 是否 ≥0.3**：低于就加管或调 Nt（上界只受计数能力限制，不受 MSS 适用域限制）；
5. **μ 与参照量级**：差 10 倍以上，先怀疑单位；
6. 还不对 → 跑 `python3 run.py --doctor` 看环境（缺依赖会自动装）；仍有问题再 `python3 selftest.py`。

# 附录：`optimize` 报告每节在说什么

> 你跑了 `windowcalc optimize --strain 菌株卡.yaml --protocol 协议卡.yaml`，得到一份分节的报告（固定 1/2/3/4/5/6/7 节；配了保护区会多 1b/1c，配了 inducer 多 2b，末尾还有附录 A 复现信息）。
> 下面是"人话版"导读：每节看什么、怎么用它做决定。

## 报告头

```
> 菌株：example-strain｜引擎 v0.7.0｜生成：2026-10-29 17:42
> 参数实测率：0/7｜剂量轴：按协议卡 doses_available
> 输入协议：pulse 18 h @ 0.3 mM → 推荐 24 h @ 3 mM
```
**实测率 0/7 = 这 7 个可溯源参数里一个都没实测**（td/Nt_saturation 等结构参数在附录 A 单列），全是假设值。这时报告只能当"占位方案"，
不能当预测。先看第 7 节知道缺什么。

> **报告开头现在有一行"怎么读"**：第 1 节选方案 → 第 6 节看红灯 → 第 4/5/7 节补参数 → 附录 A 复现。
> 第 1 节下面还有一行**量级锚点**（"本方案 7.6 ≈ 全强度 mutator 的 9%"），用来判断这个数算大还是小。

## 第 1 节 · 推荐方案（最重要的表）

| 列 | 人话 | 怎么判断 |
|---|---|---|
| 剂量 / T_pulse / N₀ | 三个旋钮的取值 | 这是你要照着做的实验参数 |
| **events** | 独立突变事件数（能筛到几个不同来源的克隆） | **不是菌落数**；≥ 目标克隆数即可 |
| **P(≥k)** | 拿到至少 k 个独立事件的概率 | 要 ≥95% |
| **E[乘客/克隆]** | 每个克隆平均带多少个"搭便车"的突变 | **越小越好**，这是优化的目标 |
| MC P5–P95 | **只含参数不确定性**的区间（与点估计同口径） | 与点估计差太多 = 参数没测准；带克隆间离散的另一个区间在第 4 节 |

**怎么选**：取第一行（E[乘客] 最小且 P(≥k) 达标）。若 MC 区间宽到无法接受，
说明该去补参数（第 7 节）而不是换方案。

> 如果你的菌株卡里配了 `genome_mb` + `protected`（保护区，如产物基因簇、mutator 自身），
> 表里会多一列 **P(误伤)**，后面还有 **1b 保护区账本**（每个区被打中的概率）和
> **1c 不同误伤预算下的可选方案**（预算 5% 时还能不能拿到 12 个事件）。
> 这两节是"别把产物基因簇打坏"这个要求的直接答案。

## 第 2 节 · 时刻表（这 7 个乘客是怎么攒出来的）

每个相位一行：多久、开多大（ā：0=关、1=全开）、每世系几代、每代突变率、贡献多少乘客。

**看哪一行最大，那就是要压的地方**。本例：诱导脉冲贡献 6.16（占 90%），预培养 0.12、
切换 0.33、治愈 0.02、选择板 0.18——所以优化重点是缩短脉冲，而不是纠结治愈。

> 「—」= 协议卡只给了代数没给时长；换算 h = n × td。

## 第 2b 节 · 剂量轴（只有配了 `inducer` 才有）

- `C50 / Δsat`：剂量-速率曲线的形状；
- **"当前剂量处于 97% 饱和"**：再加诱导剂只增负荷、几乎不增有效供给——这是选浓度的关键判据；
- 下面的小表：参考剂量、95% 饱和点、选定剂量各自的突变率。

## 第 3 节 · 标度律读数（一句话总结这套方案的物理）

- **ΔN**：窗口内总分裂数 = 供给的上限（涂板量就是天花板）；
- **脉冲项 vs off 泄漏项**：谁占大头。若 off 项 >20% 脉冲项，说明"关不干净"，静态公式会低估负荷；
- **"jackpot 是假供给"**：不要用抗性菌落数估"筛到几个克隆"。

## 第 4 节 · 蒙特卡洛（两套区间，别混着读）

把参数按 CI 随机采样 3000 次，给出**两个**乘客区间——它们回答的是不同问题：

1. **只含参数不确定性**（与第 1 节点估计同口径）：P50 应≈点估计。这一栏宽 = 参数没测准 → 去补参数；
2. **再叠加克隆间离散**（`clone_dispersion_sigma_ln`，默认 1.0）：克隆之间的**生物学差异**。
   这一栏**补测参数也不会收窄**——它是"同一批里不同克隆本来就差这么多"，不是测量误差。

本例：参数不确定性只有 7.2–8.0（很稳），叠加克隆间离散后是 1.5–36.5。
所以"7.6 这个数准不准"和"你挑到的那一个克隆会不会特别脏"是两个问题，
**不要拿第二栏去催自己补测参数**。

## 第 5 节 · 敏感性（tornado：先测哪个参数最划算）

每个参数单独取 CI 的上下界，看结果怎么变；**排最上面的就是最值得先测的**。

本例 `mu_supply` 让 events 从 9.1 变到 36.5（影响最大）→ 优先测 μ_supply。
（第 7 节末尾的"待测优先级"现在就是按这张表的 CI 变化自动排的，不再有第二套说法。）

## 第 6 节 · 红灯与警示（**没有这一节 = 没发现红灯**）

| 类型 | 触发 | 怎么办 |
|---|---|---|
| 🔴 红灯 | 泄漏 M_off > 3×M_base | 先解决泄漏，否则 off 相位一直攒乘客 |
| 🔴 红灯 | 背景假抗性 b·N_plated > events | 换药/换浓度，否则分不清真假抗性 |
| ⚠️ 警示 | τ_off > 6 h、剂量无 F(c) 数据、F 表与 M_on_ref 不一致 | 记录并按优先级补测 |
| ⛔ 终止 | 无可行解 | 按提示排查：μ_supply 太低 / 剂量轴不够 / 涂板量 / 背景 |

**红灯不解决，窗口数字没有意义。**

## 第 7 节 · 参数实测状态（下一步该测什么）

每个参数：值、95%CI、状态（**实测**/文献/★未测）、备注。末尾按第 5 节的 tornado **自动**给出
两条排序："对负荷影响最大"（决定乘客预算）与"对供给影响最大"（决定能不能拿到 k 个克隆）。
谁先卡住就先测谁——不再有事先写死的"τ_off 优先"。

**用法**：把这份表当实验清单——每测完一个，把实测值填进菌株卡，`status` 改成 `measured`，
重跑 `optimize`，看第 1 节的 E[乘客] 和 MC 区间怎么收窄。

---

## 一句话流程

1. 看第 7 节：实测率多少？缺什么？
2. 看第 6 节：有红灯吗？有就先解决。
3. 看第 1 节：选 E[乘客] 最小且 P(≥k)≥95% 的方案。
4. 看第 2 节：哪个相位贡献最大？那才是优化重点。
5. 看第 5 节：下一个该测哪个参数？
6. 看第 4 节：区间能不能接受？不能就回到 5。
